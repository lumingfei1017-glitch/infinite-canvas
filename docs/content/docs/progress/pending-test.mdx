# Pending Tests

The current release needs manual verification in these areas:

- Saved model selection: save a canvas node with a model, then remove its provider or remove that model while another video model remains the default. Generation, retry and pending-video recovery should keep the unavailable model selected and open configuration instead of sending a request to the default or first provider. Re-selecting a valid model should allow generation. Changing only the API key on the same provider should preserve the model; switching a config node from a valid image model to video should still use the video default.

- Local storage usage on HTTP deployments: opening the Local storage settings tab at an HTTP origin without `navigator.storage.estimate` should still show IndexedDB content statistics, display an unavailable quota instead of an error, and keep the canvas data unchanged.
- Canvas image previews: canvas image nodes, the left element list, the node reference bar, my-assets cards, the asset picker, image workbench result cards and history thumbnails, and the image/video workbench reference strips all render from a preview capped at a 768px long edge, so image-heavy views no longer decode the originals. Previews live locally only: canvas data, asset data, generation history, exported zips, and WebDAV sync must never contain preview content, and previews should be cleaned up when an image is deleted or no longer used. Opening the full-size image, editing, downloading, exporting, and generation references must keep using the original; an image that is already at or under 768px, exists only as a remote URL, or uses a custom cover should fall back to the original.
- Canvas drag and connection rendering performance: Dragging a single node, a multi-selection, or a whole group should stay responsive, and the drop position after releasing should match the dragged preview. Group highlighting should appear and disappear at the right moment when dragging nodes over a group, releasing should add them to the group, and dragging them out should remove them; dragging a group node itself should not highlight any group. When zoomed or panned so only part of the canvas is visible, every connection crossing the viewport should still render (including ones whose endpoints are both off-screen), connection click selection and the context menu should still work, and the dashed preview while creating a connection should follow the cursor as before.
- Local proxy: Settings should show a dedicated Local proxy tab between Providers and Preferences, with a switch that is off by default. Turning it on should reveal the `npx @basketikun/canvas-proxy@latest` command (with `--port` appended when a non-default port is configured), a copy action, and an address field defaulting to `http://127.0.0.1:23210` that normalizes a missing scheme and trailing slashes on blur. Test connection should succeed only while the command is running. With the proxy on, fetching model lists, generating images, videos, text (including streamed output), and audio, running custom call scripts, polling video tasks, downloading generated images and videos, and WebDAV connection tests plus sync should all route through the proxy and keep working; turning it off should restore direct requests. The proxy itself should forward request methods, headers, query strings, and bodies unchanged, stream SSE responses without buffering, and keep `data:` and `blob:` URLs untouched.
- Image and video size settings: Image settings should split resolution (`1k` / `2k` / `4k` / auto) from aspect ratio (`1:1`, `2:3`, `3:2`, `4:3`, `3:4`, `16:9`, `9:16`, `21:9`, `9:21`, auto) and fill W/H from that pair. Video settings should keep `480p` / `720p` / `1080p` (plus a custom `p` value) and `1:1` / `3:4` / `4:3` / `16:9` / `9:16` / `21:9` / auto, then fill W/H from that pair. Duration should be a 2–30 second slider with the current value on the right; auto ratio should disable W/H.
- Built-in video requests: without a custom call script, OpenAI-format channels should send `mode`, `first_frame`/`last_frame` or `image[]`, `generate_audio`, `watermark`, and reference videos/audio like the insertable template, and must not use `input_reference[]`. Gemini-format channels should use `predictLongRunning` with `image`/`lastFrame` or `referenceImages`, and must not report that video is unsupported. Refreshing the page should continue polling a Gemini task.
- Video generation mode: Video settings should offer First & last frame and General reference. One image is sent as the first frame, two images as first and last frames, and more than two images as general references even if first-and-last-frame mode is selected. Built-in requests and request scripts should use `frames` or `reference`.
- Gemini image generation: Gemini-format channels and the Gemini image call-script template should send `generationConfig.responseModalities: ["TEXT", "IMAGE"]` with `imageConfig.aspectRatio` / `imageConfig.imageSize`, and must not send `responseFormat`.
- Video request scripts: opening Call Script for a Video model should open a full-screen stepped editor. The left panel should follow Read the rules → Let another AI write it → Available variables, and list `videos` (File[]) and `audios` (File[]). Copy script brief should include the capability, variables, return requirements, and writing rules. Inserted templates should be async functions whose parameter lists unpack `params` (image templates must include `quality`, `size`, `count`, and `background`). The OpenAI video template should use FormData with `mode`, duration, size, resolution, audio, watermark, and reference images/videos/audios; `mode=frames` should send `first_frame` / `last_frame`, and `mode=reference` should send `image[]`, then poll and download `/content`. After pasting a script from another AI and saving, generating from the canvas with connected reference videos or audio should pass those files into the script.
- URL credential import: opening the app with a new valid `baseUrl` and `apiKey` should append a provider without changing existing providers; importing the same Base URL again, including trailing-slash or `/v1` variants, should update only that provider and remain idempotent; an API key without a Base URL or an invalid Base URL should leave all settings unchanged.
- Documentation navigation and page contents: at phone width, opening the documentation sidebar should show the current section and its description at the top. Expanding it should allow switching among Overview, Canvas Guide, Development, Progress, Business, and Support; the selected section and page list should update together while the desktop top tabs remain unchanged. At widths of 960px and above, a table of contents with hierarchical track lines should appear to the right of the article, support heading navigation, and highlight the current heading while scrolling; narrower layouts should keep the top collapsible contents control.
- Canvas Agent generation-flow references: when a generation prompt contains only `@[node:...]` references already passed through `referenceNodeIds`, the existing text, image, video, audio, or group nodes should connect directly to the generated config node without creating a duplicate prompt text node; prompts containing ordinary prose should continue creating their own prompt text node.

- Multi-image transparency: when a multi-image node containing transparent PNG or WebP assets is expanded, transparent areas in both the primary and alternatives should reveal the canvas; switching primary images must not introduce a white or panel-colored background.
- Canvas navigation: the canvas should open in Move mode by default, and the bottom toolbar should switch between Select and Move modes and reflect the active mode with its icon; Select should draw a clearly spaced dashed range whose dash length, gap, and stroke width remain visually constant at every zoom level, while Move should drag elements directly and pan only when dragging the blank background. - Global Dropdown, Menu, Select, Cascader, and TreeSelect popup backgrounds, hover states, and selected states in both light and dark themes.
- Canvas node resize stability: importing an image should open its prompt panel, resizing it immediately from any corner should temporarily hide the panel, remain smooth without flashing or triggering a maximum update depth error, and restore the panel after release. Prompt scrolling, generated-prompt restoration, edit-prompt persistence after closing an existing image or text node panel, expanded prompt editing with live synchronization and `@` references, image editing, drag-and-drop references, and generation configuration should continue to work.
- Text output count: both a text node's lower prompt panel and a generation configuration node in Text mode should expose an independent generation count from 1 to 15, default to one, and create that many text nodes. Changing the text count must not alter the image count, and switching a generation configuration node back to Image should continue to use the configured image count.

Clicking an image, text, or video node without dragging should open its lower prompt panel directly, while image toolbar labels can still be enabled explicitly from the toolbar settings.

- 视频反推提示词：非空视频节点的悬浮工具条应出现「反推提示词」，点击后创建分镜解析文本节点 + 生成配置节点并自动连线该视频。生成时抽取 4-12 帧 JPEG（每 2 秒一帧、超长视频封顶 12 帧），每帧长宽乘积不超过 50 万像素，每帧前标注「第 N 帧｜mm:ss.cc」并给出视频总时长；模型返回的镜头时间范围应与实际画面对得上，快速闪过的画面和转场帧也要被列出，看不清的应写「画面中无法准确判断」而不是编造；帧不含音轨，不得虚构音乐或台词。
- 反推压缩范围：只有百炼请求会把图片 data URL 压到 50 万像素以内；GPT/Gemini 反推仍发送原分辨率图片，既有的图片/视频/音频生成链路行为不变。
- 反推失败与边界：空的图片或视频节点点击后提示素材为空；无法解码的视频（如 HEVC）提示「建议改用 H.264 编码的 MP4 视频」而不是抛出原生解码错误；抽帧或流式输出途中点停止不应弹错误；视频本地素材丢失时提示素材已丢失；时长读取失败的视频应退回节点记录的毫秒时长，仍取不到时按 4 帧提交。
- 视频复刻向导（分段版）：非空视频节点的悬浮工具条里，「反推提示词」右侧是「视频复刻」。第一步改为「复刻分段」列表：可添加/删除分段、点「按全片自动分段」按 15 秒上限把长视频一次拆好（如 50 秒 → 4 段），每段显示秒数；输出时长默认「跟随片段时长」，切到「手动指定」才出滑杆，上限按最长段自动算成 30−片段秒数。
- 素材复用：第二次为同一条视频打开复刻向导时，上次用过的素材图片会以「画布已有」标签自动带出，不再重复建节点；点一下缩略图可暂时排除该素材（编号自动重排）；新上传或从「我的资产」选择的图片才落成新的图片节点并记到原视频节点的复刻素材清单里，后续分段继续复用。
- 一次生成多段：确认分段与提示词后点「生成复刻视频」，应一次创建与分段数量相同的生成配置节点（标题「视频复刻 1/2/3…」），它们共享同一批素材节点和同一条原视频连线，并排队逐段生成；配置节点里的提示词开头会有一行按素材顺序排列的 @ 引用，正文的 图N / 视频N 与连线顺序一致、不会错位。
- 片段裁剪与音轨：每段生成前网关用本机 ffmpeg 裁出该区间（重编码 mp4、30fps、单边≤4096）再上传百炼；「回贴原声」时结果应带回该段原声，配合「跟随片段时长」最准，输出更长时按 `-shortest` 截断；原片段无声时报「原视频片段里没有可回贴的音轨…」。模型侧始终按无声提交。
- 非流式：反推提示词（文本节点、配置节点、重试）与复刻向导的「开始分析」都应等完整结果一次性出现，不再逐字刷新；分析中可点「停止」或关闭弹窗中断且不弹错误；AI 分析默认选中百炼渠道的文本模型（如 qwen3.8-flash），可切到其他渠道文本模型，生成模型仍单独选。

- 中断即取消云端任务：百炼视频生成过程中点节点「停止」（或关闭触发中断）后，网关日志/网络面板应出现 `DELETE /api/bailian/video/tasks/{id}`；任务还在排队时应被置为取消、不再计费，已经开始生成的会返回失败提示（此时仍会跑完计费，属模型侧限制）。任务已成功或已拿到结果后再停止不应报取消错误（前端静默忽略）。
- 复刻分段排队停止：多段复刻生成中点「停止」，应提示「已中断后续分段…」，剩余分段的配置节点保持未生成状态、不再自动提交任务；需要继续时逐个节点点「开始生成」。
- 素材地址还原：复刻向导里复用「画布已有」的素材节点做 AI 分析时，请求里的图片应全部是 `data:image/...` 或公网 http(s) 地址；素材已失效（本地存储丢失）时应提示「有参考图无法读取（可能是已失效的本地地址），请重新选择素材后再试」，而不是百炼的 InvalidParameter URL 报错。多段长视频时按段数分摊抽帧，单次分析总帧数不超过 24 帧。
